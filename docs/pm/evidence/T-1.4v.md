## AC-3 Accepted mutations, classified

1. **DEF (S2): varying-header endpoints skip cell typing, row width, header order and extra columns.** `commonplayerinfo` and `leaguestandingsv3` schemas were generated from samples whose headers differ (raw cache, multiple seasons), so `ingest/contracts.py:101-122` takes the "varying" branch: it requires only the shared headers and `rowSet` items `minItems` = shared count, with no `prefixItems`, no `maxItems`, no `const` on headers. Accepted: type change (CommonPlayerInfo PERSON_ID int→string; Standings), header swap (both), added EXTRA_COL (both), truncated row (Standings). The module docstring (`contracts.py:10-11`) promises exact cell count and per-cell type for every result set. Consequence: a changed column type reaches staging. Plan 1.4 done-when still literally passes (renamed/missing shared columns are caught), so this does not fail the Gate 1 item, but it is a real gap against 1.4's stated intent. Suggested fix (PM to route to developer): add per-cell type and width checks in the varying branch, using the shared-column positions per row.
2. **Known R-013 (zero rows accepted), wider than recorded.** An empty `rowSet` passes on all 13 endpoints, not only `playercareerstats`. Not required by the 1.4 done-when, so not a defect against 1.4. Recommend R-013 scope be widened to all endpoints (PM to decide).
3. **Spec gap / by design (S4): null in a non-key cell accepted** on all endpoints. `contracts.py:126-131` allows null for non-key columns by design (untracked stats are NULL). Not a defect.
4. **Spec gap / by design (S4): unexpected key inside a `scheduleleaguev2` game object accepted.** That schema is hand-written and its `$comment` says it covers only the fields the anomaly check reads. Not a defect, but a schema drift in that endpoint's game objects will pass silently.
