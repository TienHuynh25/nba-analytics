## What changed

- Gold annotation: new optional `gold.value.allowed`, a list of `{metric, value, column, key?}`
  (same shape as `answer` items), validated by `eval/schema.py` `GoldNumber` + `Gold._allowed`.
  Produced only by `eval/gold/compute_gold.py` (`ALLOWED` per block id; `allowed_numbers()`):
  - Q43: `conference_rank` (tag games_played), `win_pct`
  - Q57: `home_pts`, `away_pts` (game_points)
  - Q62: `league_points_per_game` of the seasons outside the comparison
  - Q72: `centers_avg_usage_rate` (usage_rate), `centers` (games_played)
  - Q73: `made` (field_goals_made), `share` (shot_fg_pct)
  - M03 turn 2: `threes_made`, `threes_attempted`, `pooled_three_point_pct` (three_point_pct)
  Inherited by paraphrases: 16 units in total (T-2.15b-2.log).
- Numeric scorer (`eval/harness/numeric.py`): a stated number passes if it matches a required or
  allowed number under the registry rounding, or a resolved argument; season/date tokens pass if
  they are arguments or appear in the gold rows; digit-bearing names in the gold rows
  ("Philadelphia 76ers", "Left Corner 3") are blanked as exact text first. Everything else is
  unverified; every required number must be stated. The gold row count is allowed (the app
  verifier allows it too).
- `scorers.gold_numbers` / `attach_gold` read `value.answer` (required) and `value.allowed`
  explicitly. The old walker in test_eval.py counted every `{metric, value}` anywhere as
  required, so it would have turned allowed numbers into required ones.
- `sql_rows`: reads `value.rows` (or `candidates` for clarify; a legacy list of rows still
  works). Row counts must be equal, so a LIMIT that drops a tied row fails. Each scored gold
  column (the required numbers' columns, or every column when there are none) must map to its
  own result column with equal values under the registry rounding. Order is checked only when
  `ordered: true`.

## Findings

- Knowledge answers and name-only answers (Q79, M05.1) cannot pass the answer stage until the
  judge exists (2.20).
- Q27's "two-season average" context number is not in its gold rows, so it cannot be allowed.
  Its block would need an extra column.
- `compute_gold._check_display` is defined but never called. The T-2.6 claim that the "6-decimal
  display check runs" is not true in the code.
- App-side, the verifier does not blank names with digits ("76ers", "Corner 3"), so these may
  be rejected there. The harness passes `rec.args_text` without the row seasons that the
  verifier accepts.
- A natural language date ("Jan 15") or "2OT" in a Q57 game list is still unverified.
